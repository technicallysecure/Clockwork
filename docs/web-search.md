# Public web research

Type `Search the web for RFC 9309 Robots Exclusion Protocol` in ordinary chat. Clockwork sends the terms after “for” to the agent’s SearXNG service. The application dispatches the `web_search` tool directly, so this works even with native tool calling off. Use `/search` followed by the exact public terms for a complex query. Clockwork also recognizes “Please search the internet for …” and “Look up … online”. For a request that needs context from your conversation, enter the public terms you want searched.

You can also open **Web search** below the message box, enter a query, and select **Search web**. The field starts empty and leaves your chat draft in place. Both paths display numbered source links, domains and snippets. The selected model can summarize the evidence with matching source numbers. **Read page** displays a text excerpt directly in Clockwork. Opening the title instead visits the publisher in your own browser.

## Enable search

1. Include `compose.search.yaml` alongside the existing Compose files. On Core‑2 with Windows PowerShell, the private `.env` can set `COMPOSE_FILE=compose.yaml;compose.plan.yaml;compose.search.yaml`. Keep your existing project name and volumes. Omit the plan file on an installation that uses only the API-key and LM Studio profiles. The search service uses no API key.
2. With `CLOCKWORK_LOCAL_ONLY=false`, run `docker compose up -d --build --wait`. The search overlay sets `CLOCKWORK_WEB_SEARCH=true` in the workers. The default deployment and local-only mode both keep web tools disabled. To select files explicitly from WSL, use `docker compose -f compose.yaml -f compose.plan.yaml -f compose.search.yaml up -d --build --wait`.
3. Choose **Enable web search** below the message box, or open **Agent settings** directly. Select the inference profile, check **Allow web search for this profile**, review and save. Each worker, profile and ChatGPT plan registration has an independent setting. A disabled checkbox explains which deployment setting or permission controls it. Search requires the `web_search` tool and `web.search` permission. Reading a result additionally requires `read_web_source` and `web.read`. An operator can grant search alone. Turning the setting off blocks subsequent reads and scheduled searches for that context.
4. For a recurring query, create a follow-up with `web_search` and fixed arguments, for example `{"query":"SearXNG release notes"}`. The scheduler uses the exact approved arguments. Choose the nonempty condition for an inbox notification when results exist. Run history records an upstream outage as a failure if retries exhaust the budget.

Each worker gets a separate SearXNG container. Its private network and DNS alias connect it to that worker alone. The sidecar has a read-only filesystem, temporary cache, a read-only engine configuration, and no published port or agent credentials. Docker logging for the sidecar is disabled because upstream diagnostics can contain query text. The image is pinned by digest. The Windows isolation check verifies the worker networks, mounts and port bindings.

## Where the data goes

| Operation | Data sent | Destination |
| --- | --- | --- |
| Search | The submitted query and fixed search options | The worker's SearXNG instance and its configured engines, DuckDuckGo and Mwmbl |
| Summarize | The question, result titles, links and snippets, plus any approved source text read in the turn | The currently selected model provider |
| Read a page | DNS lookups, a robots request and a bounded HTTPS GET | The resolver and the source website |

The search providers can see the terms and the deployment's outbound address. Publishers see the requested path and query string. Use public terms in the search field. Reachability, rankings, rate limits, robot exclusions and the coverage of individual engines vary. A genuine empty result and a search service failure have different outcomes.

## Design decisions and research

- **Keep private context in Clockwork.** The worker constructs a research request from the owner-entered query and public results. It excludes conversations, saved preferences, commitments, goals, workspace files and credentials. The owner can inspect research turns in the same transcript. Ordinary model turns exclude those entries. Providers keep their existing isolation boundaries. Local-only mode blocks all search and page reads.
- **Use a fixed search API.** SearXNG supports a form POST and JSON results. Clockwork selects the two engines in the deployment configuration, rejects special routing prefixes, requests strict safe search, and accepts at most five public HTTPS results. Per-engine support determines the effect of the content filter. [Search API](https://docs.searxng.org/dev/search_api.html) · [Search syntax](https://docs.searxng.org/user/search-syntax.html) · [Engine configuration](https://docs.searxng.org/admin/settings/settings.html)
- **Treat retrieved text as evidence.** Search and site text may contain instructions intended to redirect an agent. Clockwork gives the research model only the optional source reader. The worker verifies an opaque result ID against the current query and allows at most one model-selected page. Its final synthesis request carries zero tools. Ordinary chat cannot submit search terms through a fabricated native tool call. Manual reads recheck permissions, worker, profile and stored source. The UI renders excerpts as text and builds external links from stored source metadata. [OWASP prompt-injection prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)
- **Constrain outbound connections.** The reader accepts public HTTPS hostnames on port 443. It checks all returned DNS addresses, pins an approved address for the connection, and verifies the TLS certificate against the original hostname. Redirects must stay on the approved origin. This protects Core‑2, private services, loopback and special-use addresses from a malicious result or a DNS change. The reader sends no user cookies, API keys or authorization headers. [OWASP server-side request forgery prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) · [IANA IPv4 registry](https://www.iana.org/assignments/iana-ipv4-special-registry/) · [IANA IPv6 registry](https://www.iana.org/assignments/iana-ipv6-special-registry/)
- **Respect the publisher and bound the work.** The reader checks `robots.txt` for `ClockworkReader`. A missing policy permits a read, while an inaccessible policy or a disallowed path stops it. HTML and plain text are supported. Requests have deadlines, compressed and expanded response limits, and a 12,000-character excerpt limit. The HTML parser extracts text without executing scripts or fetching embedded resources. JavaScript-only pages and PDFs need a different reader. [Robots Exclusion Protocol](https://www.rfc-editor.org/rfc/rfc9309)

## Verification

Run `npm ci --ignore-scripts` and `npm test` with Node 24. The web tests use controlled transports for DNS, redirects, private-address rejection, robots rules, size limits, injected instructions, scoped source IDs, disabled grants and scheduled queries. For a manual smoke test, search for `RFC 9309 Robots Exclusion Protocol`, open a returned public source with **Read page**, and check that the excerpt belongs to the displayed publisher. A model outage should leave successful search results available.

All 88 tests passed on Windows and in the Linux runtime container with outbound networking disabled. A separate browser test exercised authenticated search, source display and page reading using controlled web and model responses. On Core‑2, a live search from the personal worker returned five sources, and its reader retrieved the RFC Editor's text. The smoke test used an in-memory database to keep test traffic out of the owner's transcript. LM Studio's configured endpoint was unreachable during that test, so the live turn displayed the sources with a summary-unavailable message. Model synthesis and its restricted tool round trip were verified with fixtures.

On November 23, 2026, the ChatGPT plan worker on Core‑2 received `Please search the internet for RFC 9309 Robots Exclusion Protocol` through the ordinary chat endpoint. With native tool calling off, one SearXNG search returned five public sources including the RFC Editor. One plan-backed inference request to `gpt-6.1-terra` produced a cited summary. This test used temporary history. The updated suite passed all 94 tests on Windows and in the network-disabled Linux image.
